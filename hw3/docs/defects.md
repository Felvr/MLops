# Пять дефектов: причины, исправления, измерения

Исправления выполнены в коде заготовки. Проверки курса не ослаблялись.
Итоговый [журнал](check.log), [видео](check.mp4),
[машинные измерения](defect-evidence.json) и [метрики версий](versions.json).

## 1. Данные попадали в Git, не все артефакты учитывались DVC

**Причина.** В `.gitignore` отсутствовал `data/`; в `split.outs` был только
train, а validation и test не версионировались. DVC remote не был настроен.
Обычный `git add .` мог включить крупные JSONL в историю.

**Исправление.** `data/` исключён целиком, включая архив и тестовые фикстуры.
В `dvc.yaml` объявлены семь выходов данных: исходный ZIP, raw, provenance,
clean, train, val, test. DVC cache и remote остаются локальными, метрики — в Git.
Настроен относительный локальный remote; для обеих версий выполнен `dvc push`.

**Подтверждение.** `git ls-files hw3/data` возвращает **0 файлов**;
проверка 1 подтверждает наличие всех пяти обязательных выходов из задания
и remote. В Git не включены ZIP/JSONL, `.venv` или кэш; тяжёлых файлов >5 МиБ нет.

## 2. Смена версии не пересчитывала пайплайн

**Причина.** `collect` не объявлял параметры версии и источник как зависимость;
`clean` не зависел от raw. Изменение `collect.version` было невидимо для DVC.
Также отсутствовали некоторые зависимости от общих Python-модулей.

**Исправление.** В collect добавлены входной ZIP, секции `collect` и `source`,
пути и код схемы. В clean — `data/raw.jsonl`, версия и нужные модули.
Для всех стадий объявлены используемые код, данные, параметры и окружение.
`diversity` включён в путь к split через зависимость от его метрик.
Выбор версии хранится в `params.yaml` и входит в `dvc.lock`.

**Подтверждение.** Проверка 4 действительно выполняет v1 → v2: raw
**1600 → 2600**, clean **1531 → 2495**. MD5 clean начинается с
`28b97491` и `776dae2c` соответственно. Полные SHA-256 сохранены в
`versions.json`; [DVC diff](metrics-diff.md) получен штатной командой.
В тесте дополнительно проверяется код выхода каждого `dvc repro`, чтобы
старая копия файла не могла скрыть падение стадии.

## 3. Разбиение по строкам нарушало целостность групп

**Причина.** `split.py` считал размеры нормализованных групп, но затем
вызывал `row_split(len(examples), ...)`: группа при назначении сплита
игнорировалась. Отчёт контаминации вычислялся, но результат не останавливал код.

**Исправление.** Назначение производится один раз на нормализованное заболевание
через SHA-256 группы и seed=42. Все его вопросы остаются вместе. `split`
падает при пересечении train/test; отдельная DVC-стадия проверяет все три пары
сплитов по ID, текстам, группам и точному Жаккару.

**Подтверждение.** На том же clean v2 воспроизведён прежний случайный алгоритм:
**217 общих групп train/test**. После исправления — **0**. Пересечения по ID,
тексту и near-dup для этого конкретного среза были нулевыми и до исправления;
не приписываем ему чужие 19,5% утечки из лекции. В окончательном разбиении
по всем четырём осям и всем трём парам — ноль. При переходе v1 → v2 все
1531 старых примеров сохранили свой сплит и содержимое.

Измерение можно повторить: `uv run python scripts/audit_defects.py`.

## 4. Неточная дедупликация не вызывалась

**Причина.** В clean после точного сравнения оставался пустой `near = set()`.
Параметр `clean.near_dup.enabled` ничего не делал, даже если был включён.
Кроме того, LSH-кандидат в исходном helper считался дублем без проверки
реального Жаккара, что могло давать ложные срабатывания и пропуски.

**Исправление.** После ПДн и точных дублей вызывается near-dedup, её индексы
удаляются, число удалений пишется в метрики. Общий полный индекс шинглов
с точной проверкой Жаккара используется и в clean, и в contamination;
пороги принудительно равны 0,85. Для MCQ тело вопроса отделяется от вариантов:
их перестановка не позволяет дублю выжить.

**Подтверждение.** В фикстуре курса из **5 строк остаются 3**:
`dropped_exact_dup=1`, `dropped_near_dup=1`, совпадений ПДн **3**.
Отдельная регрессия с перестановкой вариантов также удаляет одну строку и
находит одну пару при межсплитовом сравнении. Индекс проверен против полного
попарного Жаккара на 147 множествах. В настоящем срезе MedQuAD близких дублей
не найдено; искусственные дубли в сдаваемый датасет не добавлялись.

## 5. Гейт разнообразия был только предупреждением

**Причина.** `violations()` уже находил нарушения, но `main()` печатал
предупреждение и завершался с кодом 0. DVC принимал вырожденный набор.
Без связи diversity → split сам граф также не гарантировал порядок гейта.

**Исправление.** Метрики записываются, затем при любом нарушении вызывается
`SystemExit` с ненулевым кодом и перечислением фактических значений и порогов.
Split зависит от метрик diversity. Пороги не снижены.

**Подтверждение.** Контрольный набор из **1200 строк** имеет **6 нарушений**:
1 системный промпт при минимуме 3, 1 группа при минимуме 50,
крупнейшая группа 100% при максимуме 10%, p90/p10=1 при минимуме 1,6,
одна длина у 100% ответов при максимуме 25%, повторы ответов 99,67%
при максимуме 30%. Процесс завершается ошибкой. Сообщение «4 нарушенных порога»
в исходном `check.sh` — число строк, совпавших с его узким grep, а не общее
число нарушений; полные шесть записаны в `defect-evidence.json`.

Настоящий v2 проходит без нарушений: **2495 строк, 4 инструкции, 650 групп,
p90/p10=15,98**. Проверки 6 и 7 зелёные.

# Паспорт датасета: вопросы о наследственных заболеваниях

**Тема:** подготовка медицинских текстовых данных для дообучения модели,
отвечающей на общие вопросы о генетических заболеваниях.
**Статус:** рабочая тема выбрана; согласование с преподавателем ещё требуется.
Модель в ДЗ 3 не обучается. Дата выполнения: 21 сентября 2026 года.

## Происхождение и лицензия

Источник — [MedQuAD](https://github.com/abachaa/MedQuAD), авторы Asma Ben Abacha
и Dina Demner-Fushman; раздел `3_GHR_QA` (Genetics Home Reference, NLM/NIH).
Используется commit `577bd37b96c02d1833b2c9eed2de9f96964e96cb`, а не меняющаяся
ветка. ZIP проверяется по SHA-256 до обработки. Лицензия — **CC BY 4.0**;
[полная атрибуция и ссылка на статью](SOURCE.md).

Данные — общедоступные образовательные тексты, не истории болезни пациентов.
Язык вопросов и ответов — английский; автоматический перевод не выполнялся.

## Что сделано с источником

1. Из 11274 XML-документов архива отобран раздел GHR с 1086 документами;
   исключены 10188 документов других областей. Таким образом, это тематическая
   переработка медицинского корпуса, а не переименование готового набора.
2. Документы отсортированы по SHA-256 относительного пути: v1 — первые 400,
   v2 — первые 650. Отбор детерминирован, v2 расширяет v1.
3. Оставлены типы `information`, `frequency`, `genetic changes`, `inheritance`.
   Вопросы `treatment` исключены: в данном разделе ответы преимущественно
   перечисляют ресурсы для диагностики и лечения. В v2 исключено 650 таких пар
   из 3250 просмотренных. Каждый оставленный тип представлен 650 парами до чистки.
4. XML преобразован в `{id, topic, messages: [system, user, assistant]}`.
   `topic` — название заболевания из `Focus`; `id` — `ghr_` + исходный `qid`.
   Пробелы нормализованы; четыре эквивалентные системные инструкции выбираются
   по хэшу ID, не зависят от версии и не содержат подсказок правильного ответа.
5. Для всех 2600 пар v2 записано происхождение в `data/provenance.jsonl`:
   путь XML, URL, qid, тип вопроса, commit источника. Ответ берётся из той же
   XML-пары; дублирующиеся ID или отсутствие обязательного qid прерывают сбор.
   Клиническая переразметка и независимая проверка правильности ответов
   **не выполнялись**. Обогащение здесь — инструкции и сведения о происхождении.
6. Порядок чистки: схема → длины → ПДн во всех ролях → точные дубли → near-dup.
   Схема проверяется до фильтрации; ошибка содержит путь и номер строки.

## Распределение длин

Длины измерены в символах Python, **не в токенах**. Фильтр вопроса: 30–4000
символов; ответ должен содержать не менее двух символов. Пороги из заготовки
не снижались. Очень короткие вопросы исключаются, что создаёт небольшой
перекос против заболеваний с короткими названиями.

| Вопрос | v2 | 56 | 78 | 107 | 149 |
| Ответ | v1 | 790 | 2051 | 3188 | 4346 |

## Разнообразие

| Проверка | Порог задания | v1 | v2 |
|---|---:|---:|---:|
| Примеров | ≥1000 | 1531 | 2495 |
| Системных инструкций | ≥3 | 4 | 4 |
| Групп | ≥50 | 400 | 650 |
| Доля крупнейшей группы | ≤10% | 0,26% | 0,16% |
| Длины ответов p90/p10 | ≥1,6 | 15,66 | 15,98 |
| Доля самой частой длины | ≤25% | 7,51% | 7,74% |
| Доля повторных ответов | ≤30% | 9,27% | 9,82% |

Все исходные пороги сохранены. Повторные ответы возможны у разных заболеваний,
например при неизвестной распространённости; одинаковые ответы на разные
вопросы автоматически не удаляются. Это ограничение содержательного разнообразия.

## Честный сплит и воспроизводимость

Сначала глобальная дедупликация, затем сплит по нормализованному названию
заболевания. SHA-256 строки `42:<группа>` задаёт число в [0,1), которое определяет
train/val/test с целевыми долями 80/10/10. Новые заболевания не меняют
назначение старых. Фактические доли v2 — 79,04% / 10,66% / 10,30%; отклонение
ожидаемо при сохранении целостности групп. Групп в сплитах — 514 / 70 / 66.

На всех трёх парах сплитов: **0 пересечений по ID, нормализованным текстам,
группам и near-dup**. Порог Жаккара словных 4-грамм равен 0,85 и един для clean
и contamination. Полный обратный индекс проверяет точный Жаккар всех пар,
имеющих общие шинглы; нет вероятностных пропусков LSH. Для MCQ из контрольных
примеров сравнивается тело вопроса без переставляемых вариантов ответа.

Стадия `split` зависит от успешного `diversity`; отдельная стадия `contamination`
проверяет и validation. Ненулевое пересечение останавливает пайплайн.

DVC фиксирует исходный ZIP, raw, provenance, clean и три сплита; Git — код,
параметры, `uv.lock`, `dvc.lock`, метрики и отчёты. Локальный remote заполнен
для обеих версий; команды воспроизведения и отправки приведены в [README](../README.md).
Версии отмечены тегами `hw3-v1` / `hw3-v2`,
[реальный вывод `dvc metrics diff`](metrics-diff.md) сохранён отдельно.
Поля `seconds` — замеры конкретного запуска и могут отличаться при повторении.

## Ограничения

- Исторический снимок образовательных материалов, не актуальные клинические
  рекомендации. Вопросы лечения и персональная диагностика не покрываются.
- Только английский язык и наследственные заболевания. Клинические записи,
  изображения, результаты анализов и обработка персональных карт не входят.
- Вопросы самого источника шаблонны; четыре инструкции не устраняют этот перекос.
- Группировка по названию не объединяет автоматически все медицинские синонимы
  и родственные заболевания. Нулевая лексическая контаминация не доказывает
  семантическую независимость. Для серьёзного обучения нужен аудит онтологий/CUI.
- Regex-фильтр ПДн покрывает почту, поддержанные форматы телефонов и даты рядом
  с маркерами рождения. ФИО, адреса и все возможные форматы он не распознаёт;
  отсутствие найденных ПДн не является полной гарантией обезличивания.
- SHA-256 закрепляет исходные байты; при недоступности GitHub нужен сохранённый
  DVC remote. Сам локальный remote не распространяется через GitHub.

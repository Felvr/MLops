# ДЗ 1 — окружение, первый инференс Qwen3 и бенчмарк

## Цель работы

Цель — собрать воспроизводимое окружение, запустить первый инференс языковой
модели и раздельно измерить время загрузки, скорость генерации и пиковую
RSS-память. Имя модели и параметры запуска должны находиться в конфигурации, а
версии программного окружения — быть зафиксированы.

## Конфигурация машины

| Параметр | Значение |
|---|---|
| Компьютер | MacBook Pro 16-inch 2019 (`MacBookPro16,1`) |
| Операционная система | macOS 26.5.1, x86_64 |
| Процессор | Intel Core i9-9880H, 2.30 ГГц |
| CPU | 8 физических / 16 логических ядер |
| Оперативная память | 16 ГБ |
| Встроенная графика | Intel UHD Graphics 630 |
| Дискретная графика | AMD Radeon Pro 5500M, 4 ГБ |
| Устройство финального инференса | CPU |
| Модель | `Qwen/Qwen3-0.6B` |
| Тип данных | `float32` |
| Python | 3.12.13 |

По таблице первой лекции машина относится к профилю x86 CPU с 8–16 ГБ RAM.
Для него рекомендована базовая модель `Qwen/Qwen3-0.6B`, поэтому она выбрана для
работы. Имя модели задаётся только в `params.yaml` и не дублируется в
Python-коде.

Сборка PyTorch видит MPS через AMD Radeon Pro 5500M. Однако `bfloat16` на этом
MPS-устройстве не поддерживается. Предварительный бенчмарк MPS с `float16`
показал медиану 0.80 токена/с. Контрольный прогретый запуск на CPU с `float32`
показал 3.59 токена/с, поэтому для финального бенчмарка выбран CPU. Для этой
модели и машины он приблизительно в четыре раза быстрее старой Radeon через
MPS.

## Зафиксированное окружение

Проект закреплён на Python 3.12 файлом `.python-version`. Прямые зависимости в
`pyproject.toml` имеют точные версии:

```text
torch==2.2.2
transformers==4.53.2
accelerate==1.9.0
numpy==1.26.4
pyyaml==6.0.2
```

Версии выбраны с учётом Intel macOS. Более новый PyTorch 2.14.0 из примера в
видеозаписи не имеет колеса для `macosx_x86_64`, поэтому не может быть
установлен на этой машине. Команда `uv sync` создала `.venv` и `uv.lock`, где
зафиксировано полное дерево прямых и транзитивных зависимостей.

В Transformers 4.53.2 тип весов передаётся через аргумент `torch_dtype`. Его
значение всё равно читается из поля `model.dtype` файла `params.yaml`.

> MLOps — это совокупность практик и инструментов, направленных на интеграцию и
> управление машинным обучением в производственные процессы. Это включает в
> себя автоматизацию, интеграцию данных, оптимизацию модели и контроль качества.

Получено 69 новых токенов. Параметр `max_new_tokens: 200` задаёт верхнюю

последовательности. В ответ не попал исходный промпт, потому что результат
обрезается по длине входных токенов. Режим рассуждений Qwen3 отключён через
`enable_thinking: false`, поэтому вывод не содержит `<think>`-блок.

## Результаты финального бенчмарка

Замер выполнен командой `make bench`. После загрузки модели проведён один
прогревочный запуск, не включённый в расчёт скорости. Затем выполнены три

| Метрика | Результат |
|---|---:|
| Время загрузки модели | 11.13 с |
| Скорость, запуск 1 | 3.39 токена/с |
| Скорость, запуск 2 | 3.28 токена/с |
| Скорость, запуск 3 | 2.99 токена/с |
| Медианная скорость | **3.28 токена/с** |

Модель до финального замера уже была скачана, поэтому время 11.13 с отражает
чтение весов из локального кэша, создание объектов модели и размещение тензоров
в памяти, но не сетевое скачивание.

Разница между максимальной и минимальной скоростью равна 0.40 токена/с, или
примерно 12.2% от медианы. Медиана используется вместо среднего, поскольку она
устойчивее к единичной фоновой нагрузке ОС. Показатель RSS относится ко всему
Python-процессу: модели, PyTorch, Transformers, токенизатору, временным тензорам
и служебной памяти.

Машина достаточна для `Qwen/Qwen3-0.6B`: модель стабильно помещается в 16 ГБ RAM,
пиковое потребление процесса составляет около 4.6 ГБ, а инференс завершается без
ошибок. Более крупная модель на CPU существенно увеличила бы время ожидания и
не нужна для оценки пайплайна.

Полный машиночитаемый результат сохранён командой бенчмарка в
`docs/bench.json`. Этот файл является генерируемым и исключён из Git; значения
перенесены в данный отчёт.

## Найденные и исправленные дефекты

### 1. Имя модели было захардкожено в трёх местах

**В чём состоял дефект.** Строка с именем `Qwen/Qwen3-0.6B` находилась не только
в `params.yaml`, но также в `src/model.py`, `src/generate.py` и `src/bench.py`.
В проекте существовало несколько источников одного параметра.

**Как проявлялся.** Изменение `model.name` в конфиге не меняло модель, которую
загружал `load_model()`. Кроме того, название в консольном выводе и JSON-отчёте
могло не соответствовать фактически запущенной модели. Проверка с временной
подменой на `HuggingFaceTB/SmolLM2-135M-Instruct` завершалась бы ошибкой.

**Как исправлен.** В `load_model`, консольном выводе и отчёте имя заменено на
`params["model"]["name"]`. Теперь единственный источник имени модели —
`params.yaml`, и модель можно заменить без изменения Python-кода.

### 2. Версии зависимостей не были зафиксированы

**В чём состоял дефект.** В `pyproject.toml` были перечислены только имена
прямых зависимостей без версий.

**Как проявлялся.** Повторный `uv sync` в другое время мог выбрать новые версии
PyTorch, Transformers или NumPy. Поведение программы могло измениться либо
окружение могло перестать собираться при неизменном исходном коде. Практический
пример обнаружился на этой машине: PyTorch 2.14.0 не предоставляет сборку для
Intel macOS.

**Как исправлен.** Для всех прямых зависимостей указаны точные совместимые
версии через `==`. Командой `uv sync` создан новый `uv.lock`, который фиксирует
также полное дерево транзитивных зависимостей. Файл `uv.lock` добавляется в
репозиторий и вручную не редактируется.

### 3. Время генерации измерялось вместе с загрузкой модели

**В чём состоял дефект.** Общий таймер запускался до `load_model()` и затем
использовался для каждого измерительного прогона. Значение времени было
накопительным: в него входили загрузка и все предыдущие генерации. При этом
поле `load_time` было жёстко установлено в `0.0`, а прогрев отсутствовал.

**Как проявлялся.** Рассчитанная скорость `tokens/sec` была занижена и не
описывала скорость отдельной генерации. Каждый следующий запуск включал всё
больше лишнего времени. JSON одновременно сообщал заведомо неверное нулевое
время загрузки.

**Как исправлен.** Вокруг `load_model()` добавлен отдельный таймер. После
загрузки выполняется заданное в `warmup_runs` число прогревов. Для каждой из
трёх измерительных генераций создаётся новый таймер, а скорость считается как
число новых токенов, делённое только на время этого запуска. Итоговое значение —
медиана трёх скоростей.

### 4. Генерация не была воспроизводимой

**В чём состоял дефект.** В конфигурации использовалась температура 0.7,
включавшая случайное сэмплирование, а готовая функция `set_seed()` нигде не
вызывалась.

**Как проявлялся.** При сэмплировании следующий токен случайно выбирался из
распределения вероятностей. Два запуска с одним промптом могли давать разные
ответы, поэтому побайтовое сравнение через `diff` не проходило.

**Как исправлен.** В `params.yaml` установлено `temperature: 0.0`. Код передаёт
`do_sample=False` и использует жадную генерацию. В `src/generate.py` и
`src/bench.py` перед загрузкой модели вызывается `set_seed()` со значением из
конфигурации; функция фиксирует генераторы Python, NumPy и PyTorch.

Официальная самопроверка подтвердила, что два независимых запуска дают
идентичный вывод.

## Результат `make check`

Команда `make check` успешно прошла все пять проверок:

1. в `src/` нет захардкоженных имён моделей;
2. временная смена имени в `params.yaml` действительно загружает другую модель;
3. два запуска при `temperature: 0.0` дают идентичный вывод;
4. прямые зависимости имеют версии, а `uv.lock` существует;
5. загрузка и генерация измеряются отдельно, перед замером есть прогрев.

Зелёная автоматическая проверка дополнена ручной проверкой кода, фактическим
инференсом и заполненным отчётом.

## Предлагаемая тема датасета

**Классификация русскоязычных обращений в службу поддержки со структурированным
ответом в JSON.**

Модель получает свободный текст обращения и возвращает категорию и конкретное
намерение пользователя, например:

```json
{
  "category": "ORDER",
  "intent": "cancel_order"
}
```

Пример входа: «Хочу отменить заказ». Датасет можно собрать из обезличенных и
синтетических обращений. Качество предлагается оценивать по доле валидного JSON,
macro-F1 категории и macro-F1 intent. Формулировку темы необходимо отправить
преподавателю и получить подтверждение до начала ДЗ 3.

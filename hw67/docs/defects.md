# Четыре дефекта части A

| Причина | Исправление | Проверяемое доказательство |
|---|---|---|
| Шесть моделей писали метрики и один путь model в общий дочерний run | `src/sweep.py`: свой nested run внутри цикла, один родитель | Проверки 1, 3, 4: шесть FINISHED, разные r/lr/modules, реальные adapter_config |
| Volume artifacts объявлен, но не подключён к контейнеру | `compose.yaml`: artifacts:/mlartifacts; PostgreSQL хранится отдельно | `make check-storage`: probe до и после force-recreate; SHA256 в metrics/storage-check.json |
| Из provenance удалялись все data_* | Передаётся полный provenance, включая SHA256 обоих файлов тензоров | Проверка 2 сверяет текущие байты с tags каждого run; docs/data-provenance.json связывает подмножество с ДЗ4/5 |
| promote вычислял ratio, но не вызывал проверку gate | До первого обращения к реестру вызывается gate(run, threshold) | Проверка 6: threshold=0 отклоняет положительный loss без регистрации |

Часть A создаёт только alias candidate. Champion назначает `evaluation.cli`
после повторного расчёта метрик из сырых ответов и проверки неизменности протокола.
`src.promote` по штатному конфигу также использует candidate.

Дополнительно: библиотеки закреплены для Intel macOS/Python 3.12;
`torch_dtype` совместим с Transformers 4.56.2. Вход — неизменные целые примеры
ДЗ5 (32/8, максимум 256 токенов), проверенные по исходным тензорам ДЗ4.
Scorer отклоняет лишние поля, дубли JSON-ключей, неверные метки и пустые наборы.
Gate проверяет counts по per-item, совместимость id/срезов и все behavioral-кейсы.
Исходные преподавательские tests/ сохраняются побайтово.

При первом реальном запуске выявлено требование MLflow к pip в окружении uv.
Добавлен pip 25.2; пакет модели фиксирует единственную фактическую версию torch
из окружения запуска. Это устраняет конфликт двух platform-marker требований
в дедупликации MLflow. Первый неудачный sweep остаётся FAILED в сервере;
итоговое сравнение использует только новый завершённый sweep.

При итоговой загрузке пакета из нового процесса один sync worker сервера
не успевал обслуживать параллельные скачивания за HTTP-лимит 10 секунд.
Число workers увеличено до четырёх, тесты и их таймауты не изменены.
После изменения compose проверка force-recreate и SHA256 выполняется заново.

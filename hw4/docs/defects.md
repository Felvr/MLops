# ДЗ4: четыре дефекта и подтверждение исправлений

Вход — собственный MedQuAD / GHR из ДЗ3, версия v2: 1972 диалога train и
266 val. Test не используется при выборе лимита. Числа курса на другом
датасете сюда не переносились. Результаты получены токенизатором
Qwen3-0.6B с закреплённой revision; веса модели не загружались.

## 1. Промпт попадал в лосс

**Было.** `mask_prompt()` возвращал копию всех `input_ids`, а длина промпта
была равна нулю. Таким образом, каждый токен вопроса и системной инструкции
становился целевым. Модель обучалась воспроизводить вход; низкий лосс не
доказывал качество ответов. Обучение модели для проверки этого дефекта
не проводилось: ошибка видна непосредственно в метках.

**Исправление.** Полный диалог и промпт проходят через общий шаблон. По
совпадению токенов находится граница ответа, а при склейке BPE используется
символьное смещение. Токен, пересекающий границу, маскируется целиком.
До границы `labels = -100`, после неё метки совпадают с `input_ids`.
Граница ограничена длиной обрезанной последовательности, поэтому размеры
меток и входа одинаковы даже при потере всего ответа. Такие примеры исключаются
с отдельным счётчиком. Пустой блок рассуждения Qwen3 при
`enable_thinking: false` остаётся в промпте и не обучается как ответ.

**Подтверждение.** При итоговом лимите 768 в train сохранено 477798 токенов,
из них 380951 под лоссом; 96847 позиций промпта исключены (20,27%).
На том же исправленном шаблоне без маски под лоссом были бы все 477798 позиций.
Доля ответа здесь около 79,73%, а не 9,1% из лекции: это другой датасет.
Проверка №1 декодирует метки каждого из 1972 сохранённых примеров и сравнивает
с исходным ответом (для обрезанных — с его префиксом). Регрессионный тест
дополнительно проверяет EOS и маскирование предыдущего ответа в многоходовом
диалоге. При искусственном длинном промпте выброшен 1 из 2 примеров,
а доля обрезки осталась 50%, без занижения знаменателя.

## 2. Разные шаблоны обучения и инференса

**Было.** Инференс использовал официальный шаблон токенизатора, обучение —
ручную сборку строк `TURN`. Она не воспроизводила служебный пустой блок
рассуждения Qwen3. Модель могла обучаться на одном формате, а получать другой.
Проблема именно в расхождении форматов; утверждать, что любой записанный строкой
спецтокен обязательно разбивается BPE, неверно: зарегистрированные спецтокены
токенизатор может распознать и в строке.

**Исправление.** Оба пути используют один вызов шаблона в `src/prompt.py`,
различаясь только флагом генерации и наличием последнего ответа. Функция
поддерживает также настоящий инференс: список сообщений, заканчивающийся
пользователем. В коде стадии проверяется префикс до построения меток;
при несовпадении обработка останавливается.

**Подтверждение.** Проверка №2 сверяет побайтовый префикс на всех 266 диалогах
val. Всего один модуль вызывает `apply_chat_template`, в `src/` нет вручную
заданных маркеров ролей. Дополнительный тест получает одинаковый промпт из
полного размеченного диалога и из диалога без ответа. Проверка выполняется
также для каждого train-примера при токенизации. Режим без рассуждений описан
в [карточке Qwen3](https://huggingface.co/Qwen/Qwen3-0.6B).

## 3. Паддинг оставался справа

**Было.** В параметрах было написано `left`, но этот параметр не передавался
токенизатору. Коллатор по умолчанию использовал `right`. При генерации батчем
последняя позиция короткого промпта оказывалась pad; одиночный пример скрывал
ошибку, потому что дополнение не требовалось.

**Исправление.** Сторона из параметров присваивается токенизатору, сохраняется
в `train.pt` / `val.pt` и метриках. По умолчанию коллатор дополняет слева до
максимальной длины текущего батча. На дополнении `attention_mask = 0`,
`labels = -100`; настоящие входные токены сохранены. Правый паддинг для
обучения сам по себе не всегда ошибочен; здесь левый нужен по контракту ДЗ
и для совместимости с батчевой генерацией decoder-only.

**Подтверждение.** Проверка №4 сверяет параметры, метаданные файлов и реальный
батч. В дополнительном тесте последовательности длиной 2 и 4 дают форму
`(2, 4)`, а не `(2, 768)`. У короткой строки маска внимания `[0, 0, 1, 1]`,
метки `[-100, -100, -100, 12]`: обе добавленные позиции исключены из лосса.
Реальная генерация и обучение в ДЗ4 не запускались.

## 4. Молчаливая обрезка и слишком короткий лимит

**Было.** Поле `truncated` вычислялось внутри примера, но не агрегировалось:
`truncation_stats()` возвращал пустой словарь. Отчёт не показывал потерю
хвоста ответа. Начальный `max_seq_len = 232` был выбран для другого набора.

**Исправление.** Статистика считается по всем входным строкам, до отбрасывания
примеров без обучающих позиций. Сохраняются абсолютное число, доля и число
полностью потерянных ответов; при превышении неизменённого порога 5% выводится
предупреждение, а официальная проверка №5 не проходит. Вторая часть исправления —
выбор длины по фактическому распределению, а не только добавление счётчика.

**Подтверждение.** `metrics/length_sweep.json` воспроизводится стадией `lengths`.
Сравнение выполнено после исправления шаблона, на одинаковых полных диалогах:

| Лимит | Обрезано train | Обрезано val | Потеря токенов ответа train / val |
|---:|---:|---:|---:|
| 232 | 917 / 1972 (46,50%) | 128 / 266 (48,12%) | 137892 / 22352 |
| 512 | 121 / 1972 (6,14%) | 23 / 266 (8,65%) | 13141 / 2844 |
| **768** | **7 / 1972 (0,35%)** | **3 / 266 (1,13%)** | **805 / 123** |
| 1024 | 0 | 0 | 0 / 0 |

p99 составляет 689 токенов в train и 758 в val; максимумы — 999 и 865.
Лимит 768 покрывает область около p99, удовлетворяет порогу и ограничивает
самые длинные батчи. Из 381756 исходных обучаемых токенов train потеряно
805 (около 0,21%); полностью потерянных ответов — 0 в обоих сплитах.
1024 сохранил бы всё, но допустил бы более длинные последовательности;
768 — осознанный компромисс. Обрубленным ответам EOS искусственно не добавляется.

## Воспроизводимость и проверяющий скрипт

`tests/check.sh` сохранён побайтово из архива: SHA-256
`f2002c8c9519f919ef53bed7ba3f962a1d83cc021ce9dd5e36ab5bbb266a2bbb`,
короткий отпечаток **f2002c8c9519**. Изменений проверяющего скрипта нет.
`make sample` оставлен как совместимый псевдоним подготовки собственного ДЗ3,
чтобы исходная проверка могла восстановить отсутствующие входы без parquet курса.

DVC описывает подготовку, токенизацию, отчёт и исследование длин; версии зависимостей
закреплены `uv.lock`, токенизатор — commit SHA. Данные и файлы `.pt` остаются
в игнорируемой папке `data/`. Контрольные SHA-256 сплитов есть в `metrics/input.json`
и `metrics/tokenize.json`. Packing отключён: без отдельной блочной маски внимания
его включение изменило бы задачу. Дополнительные тесты расположены отдельно
от проверок преподавателя. Логи запусков — `docs/check.log`, `docs/regressions.log`
и `docs/repro.log`.

Прогноз использует реальные 3,28 токена/с генерации из отчёта ДЗ1 на Intel CPU.
Это условная оценка по формуле лекции, а не измеренная скорость обучения;
фактическое время и память предстоит проверить в ДЗ5.

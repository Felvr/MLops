# Правила проекта MLops

## Один проект и один репозиторий

Корневая папка `MLops/` — единственный Git-репозиторий для всех домашних работ.
Текущая рабочая ветка — `MLops`, remote `origin` — `https://github.com/Felvr/MLops.git`.
Git-команды выполняются из корня; отправка этой ветки публикует все готовые ДЗ вместе.

Не создавай для очередного ДЗ отдельный репозиторий, вложенную `.git`, submodule,
отдельную ветку или копию всего проекта. Меняй эту организацию только по прямому
указанию пользователя. Новая домашняя работа — новая папка `hwN/` в этом проекте.

## Структура

```text
MLops/
├── .git/
├── .gitignore
├── .gitattributes
├── AGENTS.md
├── agent.md
├── README.md
├── hw1/
├── hw2/
└── hw3/                 # следующие работы добавляются аналогично
```

Называй папки готовых работ `hw1`, `hw2`, `hw3` и далее, без ведущих нулей.
Не добавляй к их именам `broken`, `ready`, `final`, `copy` или номер версии.
Дорабатывай существующее ДЗ в его папке, а не создавай несколько готовых вариантов.

## Что должно быть в папке готового ДЗ

- Рабочий код и необходимые для запуска ресурсы.
- Конфигурация, описание зависимостей и lock-файлы.
- Команды запуска, README и относящиеся к работе проверки.
- Готовые материалы для сдачи: отчёт, таблица, графики, результаты эксперимента,
  видео или другие файлы, которые требуются условием.
- Доказательства результатов, если они нужны для проверки отчёта, например JSON
  замеров и журнал итоговой проверки.

Не считай обязательные отчёты, XLSX или `uv.lock` мусором только потому, что это
не исходный код. Не исключай все JSON, изображения, таблицы или видео по расширению:
среди них могут быть результаты, необходимые для сдачи.

В папке готового ДЗ не должно быть копии исходной заготовки, незаполненного шаблона,
лекций, архивов передачи, резервных копий или временных скриптов подготовки.
Оставляй вспомогательный скрипт в Git только если он нужен для запуска, проверки
или воспроизведения сдаваемого результата.

## Что остаётся локально под .gitignore

Лекции, условия, исходные `*-broken` и архивы, добавленные пользователем в корень,
можно читать и использовать, но нельзя включать в коммиты готовых работ.
Черновики, промежуточные варианты, инструменты разовой подготовки и резервные копии
размещай в `.local/` корня или в явно игнорируемых папках материалов.

Окружения `.venv`, скачанные веса и кэши, `__pycache__`, временные файлы, настройки IDE
и `.DS_Store` не публикуются. Окружение создаётся отдельно в каждой работе по её
lock-файлу. Веса загружаются в локальный кэш, а не коммитятся вместе с кодом.

Корневой `.gitignore` исключает всё в корне по умолчанию и разрешает только папки
`hwN/`, README, инструкции агенту и настройки Git. Правила для мусора внутри ДЗ
тоже должны действовать. Для специфических временных файлов работы можно дополнить
её локальный `.gitignore`. Проверяй необходимые исключения, если условие требует
файл, который оказался под игнором.

Не удаляй пользовательские исходные материалы ради чистого Git. Оставляй их на диске
под игнором. Если лишний файл уже отслеживается, убирай его из индекса с сохранением
локальной копии. Не переписывай старую историю ради очистки текущей структуры.

## Порядок работы над следующим ДЗ

1. Прочитай условие и материалы, проверь текущую структуру и состояние Git.
2. Создай `hwN/` или продолжи существующую папку нужной работы.
3. Помести туда только реализацию и комплект для сдачи, сохрани результаты других ДЗ.
4. Выполни необходимые проверки; в отчёте используй реальные измерения.
5. Обнови корневой README: добавь работу, краткое содержание и ссылку на её отчёт.
6. Перед коммитом проверь `git status`, состав добавленных файлов и `.gitignore`.
   Убедись, что нет вложенного репозитория или Git-ссылки вместо файлов ДЗ.
7. Git-операции выполняй в корневом репозитории. Публикуй на GitHub, когда пользователь
   просит отправить изменения; не создавай новый remote для каждого ДЗ.

При простой реорганизации файлов не запускай заново дорогостоящие ML-эксперименты,
если код и условия не менялись. Проверь сохранность файлов, пути, ссылки и правила Git.

Команда отправки из корня проекта:

```bash
git push -u origin MLops
```

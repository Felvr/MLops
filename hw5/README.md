# ДЗ5 — LoRA на собственном MedQuAD

**Статус:** код, зависимости, входные данные и короткие пробы проверены.
Основные прогоны, графики, сравнение, итоговый отчёт и девять проверок
вы выполните позже по инструкции ниже; реальные итоговые числа ещё не получены.

Решение продолжает ДЗ3 и ДЗ4 в одном корневом Git-репозитории `MLops`.
Базовая модель — **Qwen/Qwen3-0.6B**, фиксированный revision
`c1899de289a04d12100db370d81485cdf75e47ca`. Тема — англоязычные ответы о
генетических заболеваниях из MedQuAD (GHR), а не русские тесты НМО из шаблона.

## Подготовка и запуск

Из корня проекта:

```bash
cd hw5
uv sync --locked
make prepare
make repro
make report
make test
make check
```

`make prepare` копирует **без изменений** собственные `train.pt` и `val.pt` из
ДЗ4; хеши и происхождение записываются в [docs/data.md](docs/data.md).
Если тензоров ещё нет, сначала восстановите данные ДЗ3 и выполните `make repro`
в ДЗ4 по [его инструкции](../hw4/README.md).

`make train` выполняет два независимых прогона с одним seed: LoRA на слоях
0–27 и только на слоях 14–27. Затем рисует обе кривые train/val.
`make report` заполняет разбор пяти дефектов числами из полученных метрик.
`make repro` управляет теми же прогонами и записывает `dvc.lock`.
`make compare` сравнивает базу и сохранённый адаптер `all_layers` на пяти
заранее выбранных вопросах val; [происхождение вопросов](docs/prompts.md).
Декодирование жадное, системная инструкция совпадает с ДЗ4.

## Конфигурация и воспроизводимость

Все параметры находятся в `params.yaml`. Для полного прохода по 1972 примерам
поставьте `train.max_steps: null`; один проход с эффективным батчем 8 даёт
247 шагов, включая неполный последний батч. При изменении кода, данных,
train-конфига или lock-файла нужно заново выполнить `make repro`.

На этом Intel Mac контрольный прогон выполняется на CPU: 20 шагов из возможных
247 за эпоху, вся val-часть из 266 примеров. Это осознанный аппаратный лимит,
а не полная эпоха. Пробный прогон на Radeon Pro 5500M оказался медленнее CPU.
`gradient_checkpointing` выключен при текущем батче 1: на этом Mac в пробе
CPU с двумя шагами пик RSS был 2,6 ГБ; при нехватке памяти включите его.

На Intel macOS окружение закрепляет PyTorch 2.2.2 и NumPy 1.26.4;
новые macOS-сборки PyTorch не поддерживают x86_64. На остальных платформах
установится PyTorch 2.5.1. Для CPU используйте `device: cpu`, `dtype: float32`;
для совместимого ускорителя устройство и тип весов задаются в конфигурации.
Повторяемость проверяется на одном железе и в одном зафиксированном окружении;
побитовое совпадение между CPU, CUDA и MPS не обещается.

```bash
# Короткая техническая проба, не заменяет результаты основных прогонов:
uv run python -m src.train --variant all_layers --max-steps 3 --val-limit 8 --out ../.local/hw5-smoke

# Весь пайплайн с контролем зависимостей:
make repro
```

DVC отслеживает входы, код, конфигурацию, окружение и адаптеры. Данные, веса и
сырые JSON-метрики исключены из Git. Отчёты и графики входят в Git. DVC cache
локален: опубликованного хранилища весов у этой работы нет; на другом компьютере
артефакты нужно воспроизвести. Git-команды выполняются только из корня `MLops`.

## Порядок личного запуска

1. Держите Mac подключённым к питанию, обеспечьте свободное место для окружения,
   кэша модели и двух адаптеров. Из корня репозитория перейдите в `hw5/`.
2. Запустите `uv sync --locked` и `make prepare`; убедитесь, что в `docs/data.md`
   показаны 1972 train и 266 val примеров и нет ошибок.
3. Запустите `make repro`. DVC выполнит оба варианта, сравнение и график
   по зависимостям, затем запишет `dvc.lock`. Дождитесь файла
   `docs/curves.png`. Команда может работать несколько часов. Не меняйте
   `params.yaml` или код после начала прогонов.
4. Запустите `make report`. Проверьте, что появились
   `docs/compare.md` с пятью парами ответов и `docs/defects.md` с числами.
5. Запустите `make test`, затем `make check`. Проверка сама выполнит два
   дополнительных коротких обучения по три шага. Запишите экран с последней
   строкой `Все проверки пройдены` и отпечатком `06a02208c1f0`.
6. Пришлите мне `docs/curves.png`, `docs/compare.md`, `docs/defects.md` и
   полный вывод `make check`; я проверю измерения и комплект перед сдачей.

Для получения логов без повторного обучения можно запустить команды так:

```bash
make repro 2>&1 | tee docs/repro.log
make report 2>&1 | tee docs/report.log
make check 2>&1 | tee docs/check.log
```

В `bash` для сохранения кода ошибки при `tee` сначала выполните
`set -o pipefail`; если есть ошибка, просмотрите конец соответствующего лога.
Не запускайте одну и ту же долгую команду повторно только ради записи лога.

## Комплект сдачи

- `docs/defects.md` — пять дефектов с числами собственного эксперимента.
- `docs/curves.png` — train/val для обоих вариантов, включая шаг 0.
- `docs/compare.md` — пять пар ответов базы и адаптера.
- `docs/check.log`, `docs/check.mp4` — вывод и видео итоговой самопроверки;
  создаются после вашего запуска.
- `docs/data.md` — размеры входа и SHA-256 тензоров ДЗ4.
- `uv.lock`, `dvc.yaml`, `dvc.lock` — окружение и воспроизводимый пайплайн;
  `dvc.lock` появится после вашего `make repro`.

Проверка преподавателя `tests/check.sh` сохранена без изменений.
Ожидаемый SHA-256 начинается с **06a02208c1f0**. Она выполняет девять проверок,
в том числе перенос копии адаптера с токенизатором без сети и два обучения
по три шага. Поэтому `make check` тоже требует времени и кеша базовой модели.
Дополнительные небольшие регрессионные тесты запускаются командой `make test`.

Пять ответов демонстрируют подключение адаптера; они не доказывают медицинскую
точность. Снижение val loss характеризует соответствие текстам MedQuAD.

`make clean` удаляет воспроизводимые выходы; `make distclean` — также окружение.

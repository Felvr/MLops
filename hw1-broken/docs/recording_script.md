# Сценарий ролика по ДЗ 1

## Перед записью

Откройте терминал в `hw1-broken` и редактор с проектом. Убедитесь, что интернет
доступен, а модели уже находятся в кэше. Выполните один раз до записи:

```bash
uv sync
make generate
make bench
make check
```

Это уменьшит паузы на скачивание. Сам `make check` всё равно занимает время,
поскольку дважды запускает Qwen для проверки воспроизводимости.

## 1. Введение — 20–30 секунд

Покажите дерево проекта и скажите:

> Цель первой работы — получить воспроизводимое окружение, выполнить инференс
> Qwen3 и честно измерить железо. В исходный проект были заложены четыре дефекта:
> хардкод модели, незафиксированные зависимости, неверный таймер бенчмарка и
> недетерминированная генерация.

## 2. Окружение — около минуты

Откройте `.python-version`, `pyproject.toml` и `uv.lock`.

Объясните:

- проект использует Python 3.12;
- прямые зависимости закреплены через `==`;
- `uv.lock` хранит точные транзитивные зависимости;
- PyTorch 2.2.2 выбран потому, что новые версии уже не имеют колеса для Intel
  macOS;
- `.venv` и веса модели не коммитятся.

Можно показать:

```bash
uv run python --version
uv run python -c "import torch, transformers; print(torch.__version__, transformers.__version__)"
```

## 3. Конфигурация и выбор модели — около минуты

Откройте `params.yaml`.

Скажите:

> Имя модели встречается только здесь. Для Intel Mac с 16 ГБ выбрана базовая
> Qwen3-0.6B. Предварительно я проверил MPS на Radeon 5500M, но CPU с float32
> показал около 3.6 токена/с против 0.8 на MPS, поэтому финально выбран CPU.
> Температура равна нулю, значит используется жадная генерация, а seed равен 42.

Объясните, что `max_new_tokens: 200` — верхняя граница, а не требование получить
ровно 200 токенов. `enable_thinking: false` убирает `<think>`-рассуждение Qwen3.

## 4. Код модели — 1–2 минуты

Откройте `src/model.py` и последовательно покажите:

1. `set_seed()` фиксирует Python, NumPy и PyTorch;
2. `load_model()` берёт имя, тип и устройство из конфига;
3. `apply_chat_template()` корректно оформляет роли и служебные токены;
4. `torch.inference_mode()` отключает градиенты;
5. `do_sample=temperature > 0` переключает sampling/greedy;
6. срез `[input_length:]` удаляет токены исходного промпта.

Ключевая фраза:

> Если изменить модель в `params.yaml`, править Python-код не потребуется.

## 5. Генератор — 30–40 секунд

Откройте `src/generate.py`. Покажите вызов `set_seed`, загрузку общей функцией и
печать имени из конфига.

Выполните:

```bash
make generate
```

После ответа отметьте, что сгенерировано 69 токенов, промпт не продублирован и
`<think>` отсутствует. Число при повторном запуске может остаться тем же; главное
— побайтовое совпадение текста при текущем окружении.

Transformers 4.53.2 может вывести предупреждение о `temperature`, `top_p` и
`top_k` из встроенного `generation_config` Qwen. При `do_sample=False` эти
sampling-параметры игнорируются; на результат и проверку это не влияет.

## 6. Бенчмарк — 1–2 минуты

Откройте `src/bench.py` и покажите три независимые части:

- таймер вокруг `load_model()`;
- отдельный цикл прогрева;
- новый таймер внутри каждого измерительного запуска.

Объясните формулу `tokens/sec = новые токены / время одной генерации`, выбор
медианы и различие единиц `ru_maxrss` на macOS и Linux.

Откройте `docs/bench.json` или выполните:

```bash
make bench
```

Озвучьте финальные результаты:

- загрузка — 11.13 с;
- три скорости — 3.39, 3.28 и 2.99 токена/с;
- медиана — 3.28 токена/с;
- пик RSS — 4558.5 МБ.

## 7. Отчёт и дефекты — 1–2 минуты

Откройте preview `docs/hardware.md`. Покажите конфигурацию машины, таблицу
метрик и четыре раздела дефектов.

Для каждого дефекта кратко произнесите три пункта:

1. что было неправильно;
2. как ошибка проявлялась;
3. какое изменение её устранило.

Отдельно покажите тему датасета: классификация русскоязычных обращений поддержки
с JSON-полями `category` и `intent`. Скажите, что формулировка подготовлена для
согласования с преподавателем.

## 8. Финальная проверка — около минуты плюс время команды

Выполните:

```bash
make check
```

Когда появятся пять зелёных пунктов, поясните:

- grep не нашёл имён моделей в `src/`;
- скрипт подменил модель на SmolLM2 и загрузил именно её;
- два вывода совпали;
- `uv.lock` и версии присутствуют;
- в бенчмарке найдены прогрев и отдельный таймер загрузки.

Завершите:

> Таким образом, окружение воспроизводимо, модель конфигурируется в одном месте,
> инференс детерминирован, а характеристики машины измерены раздельно и описаны
> в отчёте.

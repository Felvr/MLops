# ДЗ 1 по MLOps: полный гайд

## Что должно получиться

В этой работе нужно превратить выданный проект `hw1-broken` в воспроизводимый мини-пайплайн инференса LLM. В финале должны выполняться все условия:

- окружение создаётся командой `uv sync`;
- прямые зависимости имеют точные версии, а `uv.lock` существует и добавлен в Git;
- имя модели хранится только в `params.yaml`;
- `make generate` выдаёт ответ модели;
- при `temperature: 0.0` два запуска дают одинаковый результат;
- `make bench` раздельно измеряет время загрузки, скорость генерации и пиковую RSS-память;
- перед измерениями скорости есть прогрев;
- `docs/hardware.md` содержит конфигурацию машины, результаты, выбор модели и разбор четырёх дефектов;
- `make check` проходит все пять проверок;
- тема будущего датасета согласована с преподавателем.

Главная идея из лекции: меняются не только код, но также данные и модель. Поэтому конфигурация, версии зависимостей и результаты измерений должны быть воспроизводимыми и прослеживаемыми.

hw1-broken/

│   ├── __init__.py

│   ├── model.py       # загружает модель и выполняет генерацию
│   ├── generate.py    # CLI для одного инференса
│   └── bench.py       # бенчмарк

├── docs/
│   ├── bench.json     # создаётся make bench
│   └── hardware.md    # итоговый отчёт, создаёте вы
├── params.yaml        # единый источник параметров
├── pyproject.toml     # прямые зависимости
├── uv.lock            # полное разрешённое дерево зависимостей

`params.yaml` — единый источник правды. Python-код не должен знать, какая конкретно модель выбрана. Это устраняет configuration debt: для смены модели меняется одна строка конфига, а не несколько файлов.

## 3. Выбор модели и исправление `params.yaml`

Профили из лекции:

| Машина | Рекомендуемая модель |
|---|---|
| Mac Apple Silicon, 16 ГБ и больше | `Qwen/Qwen3-1.7B` |
| Базовая конфигурация курса | `Qwen/Qwen3-0.6B` |
| x86 CPU-only, 8–16 ГБ RAM | `Qwen/Qwen3-0.6B` |
| Слабая машина | `HuggingFaceTB/SmolLM2-135M-Instruct` |
| NVIDIA GPU от 8 ГБ | `Qwen/Qwen3-1.7B` или 4B, если точно помещается |

Если сомневаетесь, начните с `Qwen/Qwen3-0.6B`. Если процесс завершается из-за нехватки памяти, используйте SmolLM2. Оценивается корректность пайплайна, а не размер или качество модели.

Исправленный пример `params.yaml`:

```yaml
# Единственное место, где живёт имя модели.
model:
  name: "Qwen/Qwen3-0.6B"
  dtype: "bfloat16"
  device: "auto"            # auto | cpu | cuda | mps

generate:
  max_new_tokens: 200
  temperature: 0.0          # жадная детерминированная генерация
  seed: 42
  enable_thinking: false    # не выводить Qwen3 <think>-блок

bench:
  warmup_runs: 1
  measure_runs: 3
  prompt: "Объясни, что такое MLOps, в трёх предложениях."
```

### Почему `temperature` должна быть равна нулю

При `temperature > 0` включается сэмплирование: следующий токен случайно выбирается из распределения вероятностей. Одинаковые запросы могут давать разные ответы. При `temperature = 0` код включает жадный поиск (`do_sample=False`): на каждом шаге выбирается наиболее вероятный токен.

Seed всё равно следует фиксировать. Для жадного поиска он обычно не влияет на выбор токенов, но делает поведение явным и понадобится, если позже снова будет включено сэмплирование.

### `max_new_tokens` — это верхняя граница

Значение 200 не означает, что модель обязана создать ровно 200 токенов. Она может раньше сгенерировать токен конца ответа. Например, результат в 40–60 новых токенов является нормальным.

### Как выбрать `dtype`

- `bfloat16` уменьшает объём памяти весов примерно вдвое относительно `float32` и подходит современным GPU и Apple Silicon;
- на некоторых CPU `bfloat16` может быть медленнее либо не поддерживать отдельные операции;
- если появляются ошибки типа данных, временно установите `dtype: "float32"` и объясните это в `docs/hardware.md`.

Не копируйте выбор модели из видео автоматически. В записи использовались MacBook Pro M4 Pro, 24 ГБ и `Qwen/Qwen3-1.7B`; у вас должен быть выбор для вашей машины.

В выполненном проекте на этой машине используется Intel MacBook Pro с 16 ГБ.
Проверка показала, что MPS через Radeon 5500M доступен, но даёт только 0.80
токена/с и не поддерживает `bfloat16`. CPU с `float32` дал около 3.3 токена/с,
поэтому итоговая конфигурация — `Qwen/Qwen3-0.6B`, `device: "cpu"` и
`dtype: "float32"`.

## 4. Исправление зависимостей

Изначально в `pyproject.toml` указаны только имена пакетов. Это не обеспечивает воспроизводимость: повторная установка через месяц может выбрать другие несовместимые версии.

На этой Intel-машине используется такой набор точных версий:

```toml
[project]
name = "mlops-hw1"
version = "0.1.0"
description = "MLOPS-26, домашняя работа 1: окружение и бенчмарк"
requires-python = ">=3.12"
dependencies = [
    "torch==2.2.2",
    "transformers==4.53.2",
    "accelerate==1.9.0",
    "numpy==1.26.4",
    "pyyaml==6.0.2",
]
```

В видео на Apple Silicon использовались более новые версии, но PyTorch 2.14.0
не предоставляет wheel для Intel macOS. Поэтому версии нельзя копировать между
архитектурами вслепую. Если приведённые версии недоступны для другой ОС,
выберите совместимый точный набор и сохраните его через `==`.

После редактирования выполните:

```bash
uv sync
```

Команда создаст `.venv` и `uv.lock`. Разница между двумя файлами:

- `pyproject.toml` фиксирует прямые зависимости проекта;
- `uv.lock` фиксирует полное дерево, включая транзитивные зависимости, конкретные версии и источники пакетов.

Не редактируйте `uv.lock` вручную. Он генерируется `uv`.

Проверьте окружение:

```bash

```

## 5. Исправление `src/model.py`

Первый дефект находится в `load_model`: имя модели захардкожено в Python. Оно должно читаться из конфига.

Итоговый файл:

```python
"""Загрузка модели и сборка промпта. Общий код для генерации и замеров."""

import random

import numpy as np
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer


def set_seed(seed: int) -> None:
    """Зафиксировать источники случайности."""
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)


def load_model(params: dict):
    """Загрузить токенизатор и модель по имени из конфига."""
    name = params["model"]["name"]
    tokenizer = AutoTokenizer.from_pretrained(name)
    model = AutoModelForCausalLM.from_pretrained(
        name,
        torch_dtype=getattr(torch, params["model"]["dtype"]),
        device_map=params["model"]["device"],
    )
    model.eval()
    return tokenizer, model


def build_prompt(tokenizer, params: dict, text: str) -> str:
    """Собрать промпт с использованием шаблона чата модели."""
    messages = [{"role": "user", "content": text}]
    kwargs = {}
    if params["generate"].get("enable_thinking") is not None:
        kwargs["enable_thinking"] = params["generate"]["enable_thinking"]
    return tokenizer.apply_chat_template(
        messages,
        tokenize=False,
        add_generation_prompt=True,
        **kwargs,
    )


def generate(tokenizer, model, params: dict, text: str) -> tuple[str, int]:
    """Сгенерировать ответ и вернуть текст и число новых токенов."""
    prompt = build_prompt(tokenizer, params, text)
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
    temperature = params["generate"]["temperature"]

    with torch.inference_mode():
        output = model.generate(
            **inputs,
            max_new_tokens=params["generate"]["max_new_tokens"],
            do_sample=temperature > 0,
            **({"temperature": temperature} if temperature > 0 else {}),
        )

    input_length = inputs["input_ids"].shape[1]
    new_tokens = output[0][input_length:]
    text = tokenizer.decode(new_tokens, skip_special_tokens=True)
    return text, len(new_tokens)
```

### Сложные места в этом файле

`getattr(torch, params["model"]["dtype"])` превращает строку `"float32"` или
`"bfloat16"` в объект типа PyTorch. В Transformers 4.53.2 он передаётся через
`torch_dtype`; в новых Transformers 5.x этот аргумент переименован в `dtype`.

`model.eval()` включает режим инференса: отключает поведение обучающих слоёв вроде dropout. `torch.inference_mode()` дополнительно отключает построение графа градиентов, снижая расход памяти и накладные расходы.

`apply_chat_template` использует формат конкретной instruct-модели: служебные токены и роли `user`/`assistant`. Ручная склейка строк может дать синтаксически допустимый, но качественно неправильный промпт.

`enable_thinking: false` важен для Qwen3. Без него модель может потратить лимит первых 200 токенов на `<think>`-рассуждение вместо финального ответа.

`model.generate` возвращает последовательность `вход + продолжение`. Поэтому срез `[input_length:]` обязателен. Без него в вывод и число новых токенов ошибочно попадёт исходный промпт.

Параметр `temperature` передаётся только при сэмплировании. Это предотвращает лишнее предупреждение Transformers о том, что температура не используется при `do_sample=False`.

## 6. Исправление `src/generate.py`

В этом файле находятся ещё один хардкод имени модели и пропущенный вызов `set_seed`.

Итоговый файл:

```python
"""Генерация ответа на промпт из конфига."""

from src.config import load_params
from src.model import generate, load_model, set_seed


def main() -> None:
    params = load_params()
    set_seed(params["generate"]["seed"])

    tokenizer, model = load_model(params)
    print(f"Модель: {params['model']['name']}")

    text, n_tokens = generate(
        tokenizer,
        model,
        params,
        params["bench"]["prompt"],
    )

    print(text)
    print(f"\n[{n_tokens} токенов]")


if __name__ == "__main__":
    main()
```

Теперь и реально загружаемая модель, и имя в консольном выводе берутся из одного источника.

Запуск:

```bash
make generate
```

При первом запуске Hugging Face скачает токенизатор и веса. Это время не характеризует скорость локальной загрузки модели и не должно переноситься в бенчмарк.

## 7. Исправление `src/bench.py`

В исходнике один таймер запускается до загрузки модели и используется для всех генераций. Из-за этого:

- в скорость первой генерации попадает загрузка модели;
- в скорость второй попадают загрузка и предыдущая генерация;
- показатель становится накопительным и бессмысленным;
- `load_time` при этом жёстко равен нулю;
- прогрев отсутствует.

Итоговый файл:

```python
"""Замер производительности машины на выбранной модели."""

import json
import resource
import statistics
import sys
import time
from pathlib import Path

from src.config import load_params
from src.model import generate, load_model, set_seed


def peak_rss_mb() -> float:
    """Вернуть пиковую резидентную память процесса в мегабайтах."""
    peak = resource.getrusage(resource.RUSAGE_SELF).ru_maxrss
    return peak / (1024 ** 2) if sys.platform == "darwin" else peak / 1024


def main() -> None:
    params = load_params()
    prompt = params["bench"]["prompt"]
    set_seed(params["generate"]["seed"])

    load_started_at = time.perf_counter()
    tokenizer, model = load_model(params)
    load_time = time.perf_counter() - load_started_at

    for _ in range(params["bench"]["warmup_runs"]):
        generate(tokenizer, model, params, prompt)

    speeds = []
    for _ in range(params["bench"]["measure_runs"]):
        generation_started_at = time.perf_counter()
        _, n_tokens = generate(tokenizer, model, params, prompt)
        elapsed = time.perf_counter() - generation_started_at
        speeds.append(n_tokens / elapsed)

    report = {
        "model": params["model"]["name"],
        "device": str(model.device),
        "dtype": params["model"]["dtype"],
        "load_time_sec": round(load_time, 2),
        "tokens_per_sec": round(statistics.median(speeds), 2),
        "tokens_per_sec_all": [round(speed, 2) for speed in speeds],
        "peak_rss_mb": round(peak_rss_mb(), 1),
    }

    Path("docs").mkdir(exist_ok=True)
    Path("docs/bench.json").write_text(
        json.dumps(report, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )

    print(json.dumps(report, ensure_ascii=False, indent=2))


if __name__ == "__main__":
    main()
```

### Почему нужны три независимых измерения

1. **Время загрузки** — разовая цена запуска процесса: чтение весов из локального кэша, создание модели и размещение тензоров на устройстве.
2. **Tokens/sec** — пропускная способность только генерации. Для каждого запуска нужен новый таймер.
3. **Пиковая RSS** — максимум физической памяти процесса за всё время, а не снимок в конце.

### Почему нужен прогрев

Первый инференс может включать ленивую инициализацию, выделение буферов, прогрев кэшей и компиляцию ядер. Если включить его в измерения, результат будет занижен. Прогрев использует ту же модель и промпт, но его время не добавляется в `speeds`.

### Почему медиана, а не среднее

Разовый фоновый процесс, планировщик ОС или очистка памяти могут замедлить один запуск. Среднее заметно сдвинется, а медиана трёх измерений сохранит типичное значение.

### Что именно показывает RSS

RSS — resident set size, объём страниц процесса в физической памяти. `ru_maxrss` показывает максимум за жизнь процесса. В него входят не только веса модели, но также Python, PyTorch, Transformers, токенизатор, временные тензоры и кэши.

На macOS `ru_maxrss` возвращается в байтах, на Linux — в килобайтах. Поэтому в функции две разные формулы перевода в мегабайты.

## Найденные и исправленные дефекты

### 1. Имя модели было захардкожено в коде

**В чём состоял дефект.** Имя `Qwen/Qwen3-0.6B` находилось не только в
`params.yaml`, но и в `src/model.py`, `src/generate.py` и `src/bench.py`.

**Как проявлялся.** Изменение `model.name` в конфиге не меняло реально
загружаемую модель. Имя в консоли и JSON могло не совпадать с фактической
моделью. Проверка с временной подменой на SmolLM2 завершалась ошибкой.

**Как исправлен.** Во всех трёх местах имя заменено на
`params["model"]["name"]`. Теперь `params.yaml` — единственный источник.

### 2. Версии зависимостей не были зафиксированы

**В чём состоял дефект.** В `pyproject.toml` были только имена прямых
зависимостей без ограничений версий.

**Как проявлялся.** Повторная установка могла выбрать новые версии библиотек,
изменить поведение программы или привести к несовместимости при неизменном коде.

**Как исправлен.** Для прямых зависимостей указаны точные версии через `==`,
после чего командой `uv sync` создан/обновлён `uv.lock` с полным деревом.

### 3. Загрузка и генерация измерялись одним таймером

**В чём состоял дефект.** Таймер запускался до `load_model()` и повторно не
сбрасывался для каждого измерения. `load_time` был установлен в `0.0`, прогрева
не было.

**Как проявлялся.** `tokens/sec` включал загрузку и предыдущие запуски,
получался заниженным и не описывал скорость одной генерации. Время загрузки в
отчёте было нулевым.

**Как исправлен.** Добавлены отдельный таймер загрузки, прогрев по
`warmup_runs` и новый таймер для каждой измерительной генерации. Итог — медиана
отдельно рассчитанных скоростей.

### 4. Генерация не была воспроизводимой

**В чём состоял дефект.** `temperature` была равна `0.7`, что включало
сэмплирование, а готовая функция `set_seed()` не вызывалась.

**Как проявлялся.** Два запуска с одним промптом могли выдавать разные строки,
поэтому проверка через `diff` не проходила.

**Как исправлен.** В `params.yaml` установлено `temperature: 0.0`, а перед
загрузкой модели в генераторе и бенчмарке вызывается `set_seed()` со значением
из конфига. При нулевой температуре используется `do_sample=False`.

## 12. Типичные ошибки

### `uv: command not found`

Перезапустите терминал после установки. Если не помогло, добавьте каталог `uv` в `PATH` по инструкции установщика.

### Не удаётся скачать модель

Проверьте интернет, свободное место и доступ к `huggingface.co`. Эти модели открытые и обычно не требуют токена. Корпоративный прокси может блокировать загрузку.

### Процесс завершён из-за памяти

Выберите меньшую модель в `params.yaml`, сначала `Qwen/Qwen3-0.6B`, затем при необходимости `HuggingFaceTB/SmolLM2-135M-Instruct`. Не меняйте имя в Python-файлах.

### Ошибка или сильное замедление с `bfloat16` на CPU

Попробуйте `dtype: "float32"`. Повторите бенчмарк и зафиксируйте причину и сравнение в отчёте.

### MPS недоступен на Mac

Проверьте:

```bash
uv run python -c "import torch; print(torch.backends.mps.is_built(), torch.backends.mps.is_available())"
```

Если второе значение `False`, используйте `device: "cpu"` или установите сборку PyTorch с поддержкой MPS.

### CUDA недоступна

Проверьте `nvidia-smi` и:

```bash
uv run python -c "import torch; print(torch.cuda.is_available(), torch.version.cuda)"
```

Если CUDA-сборка PyTorch не установлена, `device: "auto"` выберет CPU.

### В ответе присутствует промпт

Проверьте срез:

```python
new_tokens = output[0][inputs["input_ids"].shape[1]:]
```

### Появляется `<think>` вместо ответа

Проверьте `enable_thinking: false` и передачу этого параметра в `apply_chat_template`.

### Transformers предупреждает про `temperature`

Не передавайте `temperature`, когда `do_sample=False`. Используйте условное раскрытие словаря, как в итоговом `model.py`.

### `make check` не проходит пункт 1

Найдите все имена моделей:

```bash
grep -rnE 'Qwen|HuggingFaceTB|meta-llama' src
```

В `src/` не должно остаться даже имени, которое используется только для печати или JSON.

### `make check` не проходит пункт 3

Убедитесь, что:

- в `params.yaml` стоит `temperature: 0.0`;
- `do_sample` становится `False`;
- `set_seed` вызывается в `src/generate.py`;
- в вывод не добавляется изменяющаяся информация вроде текущего времени.

### `make check` не проходит пункт 4

Проверьте наличие `uv.lock`, спецификаторы `==` в каждой прямой зависимости и повторите `uv sync`.

### `make check` зелёный, но решение всё равно может быть неверным

Скрипт частично использует поиск текста. Он не доказывает, что таймеры расположены правильно или что отчёт содержательный. Преподаватель дополнительно читает код и `docs/hardware.md`.
